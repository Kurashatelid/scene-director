# 2. Самый простой достаточный макет


Макет необязателен. Сначала проверь готовые сцены и заготовки камеры, света и экспорта; адаптируй подходящую вместо повторного написания всей системы. Определи 2–4 вопроса и критерии завершения. Сам выбери инструмент по проверяемой пользе и готовым заготовкам:
- 2D-аниматик — темп, композиция, реплики, порядок событий;
- Three.js — пространственная география, взгляды и камера;
- Blender — конкретные сложные контакты/анимационные опоры либо пригодная готовая сцена.

Маршрут и минимальный результат — [references/previz-delivery.md](previz-delivery.md). Свет/тени/камера сами по себе не оправдывают тяжёлый инструмент; явно выбранный движок не меняй молча. Телефонное управление, редактор маршрута и специальный интерфейс экспорта нужны только по задаче.

Различай local_check и generator_motion_input: макет может остаться локальным. Для движения, темпа и видеовхода нужен воспроизводимый проход выбранной камеры; для одной статической географии допустимы нужные виды. Для динамической задачи начни с грубого прохода всей истории и чернового звука, если он нужен для времени/реакции; для одной статической географии подготовь достаточные нужные ракурсы. Проверяй базовый свет, отбрасываемые тени, значимые жесты и согласованное влияние среды на лист, волосы, одежду/листву. Показывай реальный пользовательский вид.

После первого полного прохода (либо достаточного набора видов для статической задачи) проведи техническую и отдельную режиссёрскую проверку по [references/staging-review.md](staging-review.md). При доступном делегировании рецензент не создаёт проверяемую версию. Исправь блокеры действия, причинности, географии и обязательной видимости до зависимого этапа. Сокращай затянутые ожидания по реальному проходу в пределах открытых решений; сохраняй время на понимание и точные слова. Остановись, когда вопросы проверены, блокеров нет, ограничения названы.
