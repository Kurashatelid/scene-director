# Повторное использование материалов

## Расположение

Пользовательская папка проекта является корнем материалов. Соблюдай существующую структуру. Если структура ещё не задана, используй `work/scene-library/index.json` для каталога и метаданных, выбранные пользовательские результаты — в `outputs/scene-library/<@имя>/v001/`. Например, персонаж @Алекс хранится в `outputs/scene-library/@Алекс/v001/`, предмет @Блокнот — в `outputs/scene-library/@Блокнот/v001/`. Имя папки совпадает с handle, включая @ и регистр. В сценах сохраняй ссылки на библиотеку, а не создавай копию каждой картинки заново.

Если пользователь переключился в другую папку/чат, найди индекс в известном корне проекта и проверь доступ. Не сканируй весь диск при каждом вызове. Если корень неизвестен, запроси путь к библиотеке. Доступ к файлам проекта не гарантирует доступ ко всем папкам в других средах.

## Первое действие нового эпизода

Собери упомянутые @имена и обычные имена/названия, найди совпадения в индексе по handle, имени, роли и описанию. Обычное слово «друг» не доказывает, что это прежний @Друг: при неоднозначности покажи кандидатов. Проверь существование и доступность исходных изображений, а не только записи каталога. Одним компактным предложением покажи найденные образы, их версии и статусы: «Использовать прежние @Алекс, @Автобус… или изменить?» При необходимости покажи сами изображения. Уже выбранное в этом эпизоде повторно не согласовывай. Новую внешность не генерируй молча; отсутствие файла не означает разрешения создать замену.

Сохраняй расположение общей библиотеки в состоянии проекта и ссылку на него в состоянии сцены, чтобы новые эпизоды обращались к одному каталогу. База может быть обычным index.json с файлами; отдельный сервер не обязателен. Установка навыка не предоставляет доступ к чужому диску: при переносе в другую среду нужны доступная папка/подключённое хранилище и корректные пути. Сам каталог навыка не используй для хранения пользовательских образов.

## Запись материала

Создавай индекс только при фактическом добавлении/выборе материалов. Формат:

```json
{
  "schema_version": 2,
  "assets": [
    {
      "id": "character-bus-man",
      "handle": "@Алекс",
      "name": "Алекс",
      "kind": "character",
      "default_version": null,
      "tags": ["автобус"],
      "versions": [
        {
          "version": 1,
          "status": "proposed",
          "files": [],
          "primary_reference": null,
          "description": null,
          "identity_id": "bus-man",
          "outfit": null,
          "source": null,
          "generation_prompt": null,
          "settings": {},
          "studio_refs": [],
          "used_in": []
        }
      ]
    }
  ]
}
```

Пример задаёт структуру и не является готовым материалом. kind: character, location, prop, voice, camera, audio или video. Для каждого файла фиксируй роль (portrait, front, back, reference, camera_video и т.п.), путь относительно индекса или абсолютный путь, при возможности SHA-256. Для голоса сохраняй provider и voice ID; для ссылки студии — provider, kind и фактический asset/job ID. Для камеры сохраняй траекторию/параметры и реальные экспорты, если они есть.

## Правила @имён

- Обязательное поле handle для каждого персонажа и главного предмета; локациям тоже назначай handle. Формат: @ и буквы, цифры, подчёркивание или дефис; без пробелов, точек и разделителей пути. Кириллица разрешена. Не используй системные @img1, @vid1 и подобные обозначения входов платформы как постоянное имя.
- В пределах библиотеки одно имя обозначает один материал. Проверяй коллизии с учётом Unicode NFC и без различения регистра: @Алекс и @алекс нельзя назначать разным людям. Не транслитерируй имя самостоятельно. Двум персонажам с одинаковым именем предложи разные handles.
- primary_reference указывает на реально существующий выбранный файл, default_version — на принятую версию. Не заполняй их выдуманными путями. При отсутствии выбранного файла имя зарезервировано, но ещё не готово к генерации.
- При первом использовании в сцене разреши @имя в default_version либо явно указанную пользователем версию; зафиксируй asset ID, handle, version и конкретные файлы в scene.json/handle_bindings. Существующая сцена продолжает брать закреплённую версию. Новая версия по умолчанию меняется только при явном выборе пользователя.
- Во всех сохранённых авторских промптах, описаниях действий, ролях референсов и назначениях говорящих используй постоянные @имена. Текст диалогов сохраняй дословно. В промпте создания ещё не существующего материала handle обозначает создаваемый объект, а не якобы прикреплённый референс.
- Для разных ролей можно прикрепить несколько файлов одного персонажа, но они принадлежат той же личности и выбранной версии. Готовый файл без записи в индексе сначала индексируй. Старые записи без handle дополняй без изменения ID и ссылок сцен; чужие исходные папки не переименовывай автоматически.

## Поиск и версии

1. Прочитай индекс, отфильтруй материалы по имени/типу/тегам. Просмотри подходящие изображения и проверь наличие файлов перед использованием.
2. Если материал найден, предложи «Используем готового [имя, версия]». Явная просьба использовать выбранный материал уже разрешает повторное использование; повторное подтверждение не нужно.
3. Разделяй неизменную личность и варианты одежды. Новая одежда/ракурс — новая версия или вариант того же персонажа; новый человек — другая identity_id. Не заменяй оригинал.
4. Сцена хранит пару asset ID + version и роли используемых файлов. Обновление библиотеки не переключает старые сцены на новую версию автоматически.
5. Только пользовательское принятие переводит status в accepted. Не называй сгенерированное утверждённым по факту успешного выполнения.
6. Ссылку на исчезнувший локальный файл или недоступный ID отметь как unavailable и предложи восстановление/повторную загрузку. Не выдавай путь за прикреплённый референс.
7. Для переноса между чатами достаточно того же доступного проекта/индекса. Для другой машины нужны сами файлы вместе с индексом или действующие внешние ссылки; навык не переносит их автоматически.

Дополняй существующий индекс, не перезаписывай его пустым шаблоном. Не загружай материалы во внешнюю студию только ради индексации. Не удаляй и не перемещай исходники для наведения порядка без соответствующего запроса.
